# First-customer plan

**Goal:** use tested public work as evidence for small paid implementation jobs. This is a suggested plan, not a revenue forecast. Neither GitHub activity nor a professional-looking profile guarantees income.

## What is ready

- A profile explaining the projects without invented experience, clients or metrics.
- Two small CLIs with usage docs, automated tests and CI configuration.
- A public contact route and security-reporting guidance.

## First offers to validate

Discuss actual scope with a customer before quoting or taking payment. These are **proposed pilot prices**, not verified market rates or promised earnings:

| Offer | Specific deliverable | Suggested test price |
| --- | --- | ---: |
| Repository presentation setup | README quick start, contribution guide, issue template and a documented checklist | ₹2,000–₹5,000 |
| Basic Node project CI setup | A workflow running the client's existing tests and a handover guide | ₹3,000–₹8,000 |
| Small custom developer utility | One agreed CLI workflow, tests and installation/usage instructions | Quote after discovery; consider ₹5,000+ only for a tightly bounded task |

Do not sell security audits, production SLAs or skills you cannot demonstrate. Obtain permission before using client code or publishing a case study. Open-source code remains MIT; customers pay for your time, customization and agreed support, not exclusive ownership of the public tools.

## Next 30 days

### Days 1–7: validate the demos

- Run Trident Commit locally against Ollama and one cloud provider if you choose to incur API charges. Record the exact model, environment, sanitized example and limitations.
- Review GitHub Actions results and fix cross-platform problems before promising support.
- Record a short terminal demo yourself; do not present illustrative output as a customer result.
- Pin this profile repository and Storyboard Editor using GitHub's profile editor if desired. Repository pinning has not been changed automatically.

### Days 8–14: talk to users

- Share one useful demo with communities where self-promotion is allowed.
- Ask five developers about an actual workflow problem. No mass DMs, scraped contact lists, fake stars or unsolicited automated campaigns.
- Offer one small trial with clear scope. Keep a private record of feedback; don't publish names or private conversations without consent.

### Days 15–21: agree a paid scope

Use a short written agreement covering:
1. Exact inputs, outputs and acceptance criteria
2. Delivery date, revision limit and what is out of scope
3. Price, any deposit, taxes and payment schedule
4. Code/license ownership and whether work can be shown publicly
5. Supported environments and post-delivery support window

Use your own verified payment account. Never share financial or identity credentials in an issue or chat. For India-specific invoicing, GST, export-of-services or income-tax questions, consult a qualified professional.

### Days 22–30: deliver and learn

- Deliver a reproducible setup, tests and a handover walkthrough.
- Ask for an honest testimonial only after delivery and with permission.
- Decide whether an issue represents a reusable improvement or one-off custom work.
- Track genuine inquiries, agreed jobs, actual collected revenue, hours and costs. Avoid inventing social proof.

## Sponsors and products later

Sponsors enrollment has not been checked or configured. If you want to apply, use the official GitHub Sponsors onboarding yourself. Add a funding link only after verifying that your recipient page works.

A paid hosted service, subscriptions, npm publication and premium extensions are **not** included in this release. Consider them only after real users request a repeatable capability and you understand operating costs, privacy obligations and support burden.
